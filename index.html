The house can't change the answer. The program pays the winner.

The answer is sealed on Solana before the clue drops, and the purse is locked in a program escrow. Your guess is sealed to your own wallet, so it can't be copied by anyone else. 1 · Commit

The house stores sha256(id|salt|answer) in the contest account and locks the purse there. From that slot on, the answer can't change.

2 · Submit

You post sha256(id|wallet|guess). It's bound to your wallet, so a copied entry never counts for anyone else.

3 · Reveal & payout

The program rejects any reveal that doesn't match the seal. Every entry is then settled on chain (our reveal script does it at once; anyone can), and the program pays only when all are settled: to the earliest correct entry, or back to the house only when no correct entry exists.

Checking the program on chain…

Explorer shows program errors as hex codes. The program's codes: 0x7 reveal does not match the commitment · 0xd recipient is not the winner · 0x10 the house wallet cannot enter · 0xf not every entry is settled · 0x11 entry already settled.

What you still trust (read this)

Devnet only: every purse here is play money with no cash value. The house wallet can't enter its own contest, but the program can't stop the house using a second wallet, so this version still trusts it not to. Every entry must be settled before any payout, so no correct entry can be skipped, and the purse returns to the house only when every entry is settled and none is correct (including a contest nobody entered). Guesses are bound to their wallet, so they can't be copied; but someone holding a candidate answer can test it against other entries' hashes, so treat a sealed guess as uncopyable, not unreadable. If the house never reveals, the purse stays locked forever, so withholding a reveal can't save it money.
